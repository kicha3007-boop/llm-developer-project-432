# ADR 0001. Стек и слои сервиса генерации карточек

Статус: принято.

## Контекст

Сервис собирает черновик карточки товара по документам поставщиков (pdf, docx, xlsx). Генерация
идёт минутами, документы — недоверенные данные, за вызовы модели платят по токенам. Нужны: строгий
контракт результата, проверяемые ссылки на источники, устойчивость к рестарту воркера, учёт
стоимости и защита от инъекций и утечек персональных данных.

## Решение

- Python 3.12, FastAPI, Pydantic v2 и pydantic-settings; зависимости — uv и `uv.lock`
  (установка одной командой `uv sync --frozen`). Линтер — ruff, тесты — pytest.
- PostgreSQL 16 с pgvector (образ `pgvector/pgvector:0.8.1-pg16`), драйвер psycopg 3 и
  `psycopg_pool.ConnectionPool` — один пул на процесс (`app/core/db.py`: `pool()`, `connection()`).
- Устойчивое исполнение — Temporal (сервер разработки одним контейнером в Compose, веб-интерфейс
  на `:8233`). Статус задачи для клиента — в таблице `jobs`; история Temporal — внутренняя.
- Модель — по OpenAI-совместимому API через OpenAI Agents SDK (chat completions). Про провайдера
  знает только `app/llm/client.py`: адрес, ключ, таймауты, повторы, выбор основной/дешёвой модели,
  запись стоимости в `llm_calls`.
- Эмбеддинги — локально, sentence-transformers на CPU (`intfloat/multilingual-e5-base`, 768).
- Раскладка модулей — по контракту шага «Каркас»: `routers` (транспорт) → `services` (сценарии и
  правила) → `repositories` (весь SQL) / `llm` (вся работа с моделью) / `rag`, `parsers`,
  `guardrails`; `temporal` — оркестрация шагами поверх тех же сервисов.

## Альтернативы

- SQLAlchemy + asyncpg: прячет SQL, а проекту нужны индексы pgvector, генерируемые колонки и
  оконные функции — это проще и нагляднее на чистом SQL в репозиториях.
- Очередь (RabbitMQ + Celery) вместо Temporal: гарантирует доставку, но не знает о прогрессе
  внутри обработчика и не умеет дешёво ждать человека сутками.
- Облачные эмбеддинги: платные и отправляют тексты поставщиков наружу.

## Компромиссы

- Сервер разработки Temporal хранит историю в SQLite на томе — для учебного стенда достаточно,
  для эксплуатации нужен кластер с внешней базой.
- Повторы: вызов модели повторяет клиент (сеть/таймаут/429/5xx, экспонента с примесью), шаг —
  Temporal (`RetryPolicy` с пределом попыток и списком неповторяемых ошибок). Собственные повторы
  SDK выключены (`max_retries=0`), чтобы попытки не перемножались.

## Когда пересмотреть

При переходе к эксплуатации (кластер Temporal, внешнее хранилище файлов), при смене провайдера
модели, при росте корпуса за пределы одного узла PostgreSQL.
