# ADR 0003. Поиск: локальные эмбеддинги, pgvector, гибрид RRF и порог релевантности

Статус: принято.

## Решение

- **Модель эмбеддингов**: `intfloat/multilingual-e5-base` (278M параметров, 768 измерений,
  многоязычная, без лицензионного «гейта» на Hugging Face — посторонний человек скачает её без
  токена). Префиксы из карточки модели: запрос — `query: `, документ — `passage: `; они живут в
  настройках (`EMBEDDING_QUERY_PREFIX`, `EMBEDDING_DOCUMENT_PREFIX`), поэтому EmbeddingGemma из
  курса подключается сменой четырёх переменных (модель, размерность, два префикса) + миграция.
  Модель грузится один раз на процесс, векторы считаются пачкой и нормируются по L2.
- **Хранение**: `chunks.embedding vector(768)`, индекс HNSW `vector_cosine_ops`; метрика —
  косинусное расстояние, выбрана один раз под индекс. Колонка `tsv` — генерируемая
  `to_tsvector('simple', section || text)`, индекс GIN.
- **Почему `simple`, а не `russian`**: стеммер `russian` режет артикулы и единицы и ничего не даёт
  артикулам — а именно ради точных строк полнотекстовая ветка и нужна. Морфологию («блендера» →
  «блендер») закрывает векторная ветка гибрида. Запрос превращается в OR из `plainto_tsquery` по
  словам без служебных и вопросительных слов.
- **Гибрид**: Reciprocal Rank Fusion одной SQL-командой с `row_number()` (`chunks.hybrid_search`):
  `score = Σ 1 / (k + позиция)`, `k = 60`. Складываются позиции, а не оценки: косинусная близость
  (0.75–0.9 у e5) и `ts_rank_cd` (0.1–0.3) несопоставимы по шкале.
- **Порог релевантности** — косинусная близость, `RELEVANCE_THRESHOLD=0.80`; отсекает векторную
  ветку (и в гибриде — до слияния). Полнотекстовая ветка отсекается условием совпадения слов.
- **Досчёт векторов**: `python -m app.rag.reindex` берёт фрагменты с `embedding IS NULL` пачками,
  пишет прогресс в лог; повторный запуск — пустая работа. Индексация документа после разбора —
  отдельный шаг процесса, вызывает тот же код для одного документа.

## Калибровка порога (реальный прогон, не выдуманные числа)

Команда `uv run python -m evals.calibrate_threshold` кодирует 18 фрагментов четырёх выданных
документов настоящей моделью и прогоняет 12 контрольных запросов с известным верным фрагментом
и 6 запросов, ответа на которые в документах нет. Результат прогона 2026-10-26:

| | с префиксами | без префиксов |
| --- | --- | --- |
| близость верного фрагмента, min / медиана | 0.777 / 0.860 | 0.787 / 0.862 |
| лучший неверный фрагмент, медиана / max | 0.848 / 0.891 | 0.849 / 0.896 |
| запросы без ответа, медиана / max | 0.790 / 0.818 | 0.786 / 0.810 |
| верный фрагмент на 1-м месте | 10 из 12 | 9 из 12 |

Выводы:

1. У e5 шкала близости сжата (всё в 0.74–0.91), поэтому порог из примеров вида 0.5 не отсекает
   ничего. 0.80 стоит между медианой «мусора» (0.79) и минимумом большинства верных: на 0.80
   проходят 11 из 12 верных, а у 5 из 6 запросов без ответа лучший фрагмент отсекается.
2. Единственный верный, который 0.80 отрезает, — «фильтр от накипи» (0.777); его находит
   полнотекстовая ветка, и гибрид его возвращает (проверено на живом стенде: `vector` — 0 хитов,
   `hybrid` — 1). Это и есть аргумент за гибрид.
3. Разделить «верный» и «лучший неверный» одним порогом нельзя (0.86 против 0.85): документы одной
   тематики. Порог защищает от мусора, а не выбирает ответ — выбор делает ранжирование, а проверку —
   ссылки на источники.
4. На таком маленьком однотемном корпусе эффект префиксов слабый (ранжирование 10/12 против 9/12,
   медианы почти равны). Префиксы оставлены: это контракт модели из её карточки, и на корпусе
   побольше эффект сильнее. Порог при смене модели или префиксов калибруется заново этой же командой.

## Наблюдения на живом стенде

- «KTL-1000» и «BLD-1200»: векторный поиск ставит нужную строку первой, но соседние артикулы
  идут почти с той же близостью (0.86 / 0.84 / 0.83) — для модели это «похожие строки символов»;
  полнотекстовый находит ровно одну строку; гибрид даёт ей 0.0328 против 0.016 у соседей.
- «сколько стоит блендер оптом»: по словам находятся только фрагменты со словом «блендер», прайс
  находит векторная ветка. На крошечном корпусе почти все фрагменты проходят порог, поэтому RRF
  поднимает текстовые совпадения выше прайса — известная слабость равновесного RRF; на реальном
  объёме и с порогом это сглаживается, а для генерации берётся объединение нескольких запросов.

## Когда пересмотреть

Смена модели эмбеддингов или префиксов; рост корпуса (тогда — подбор `k`, весов веток и,
возможно, повторное ранжирование кросс-энкодером).
